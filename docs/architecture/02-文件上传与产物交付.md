# 02 文件上传与产物交付

文件在系统里有两个方向:

- **进来**:用户上传的文件怎么安全地进入会话,并被 Agent 读取。
- **出去**:Agent 生成的文件怎么检查、归档、交付给用户。

先看整体走向:

```
上传  ──►  uploads/(只读)  ──►  Agent 读取(按需转文本)
                                      │
                                      ▼
                          scratchpad/(草稿,可写)
                                      │
                                      ▼  present_files
用户下载/预览  ◄──  output/  ◄──  自检 → 归档旧版本 → 复制
```

## 1. 上传

### 1.1 没有单独的上传接口

`POST /send-message` 是 multipart 表单,文件和消息文字一起提交。
这样"上传文件"和"发起一轮对话"是同一个请求,前端不用先传文件再拿 id 去引用。

### 1.2 大小限制(`stream.py::_read_uploads`)

| 限制 | 默认值 | 超限结果 |
|---|---|---|
| 一次最多文件数 | 20 | 413 |
| 单个文件 | 50 MB | 413 |
| 一次上传总量 | 100 MB | 413 |
| 会话存储合计(uploads + output + scratchpad) | 1024 MB | 413,提示删文件或新建会话 |

重点是**读取方式**:按 1 MB 分块读,边读边累加,一旦超限立刻中止。
所以用户传一个 5 GB 的文件,服务端读到第 51 MB 就拒绝了,不会先把它整个读进内存。

注意前三项只限制"这一次请求",第四项限制"这个会话累计"。分开设是因为:一次上传再小,
多次累积也会撑满磁盘。

### 1.3 文件名清洗(`utils/filename.py`)

文件名之后会被拼进 shell 命令(Agent 要 `ls`、`python` 处理它),所以必须是 shell 安全的:

1. 只取文件名部分,丢掉目录。
2. 把空白和圆括号替换成下划线,连续下划线合并,首尾下划线去掉。
3. 清洗后主名为空,就叫 `upload`。
4. 仍含 `..`、`/`、`\` 的,退回 `upload` 加原后缀。

示例:

| 原始文件名 | 保存为 |
|---|---|
| `我的 报告 (最终).pdf` | `我的_报告_最终.pdf` |
| `../../etc/passwd` | `passwd` |
| `(  ).txt` | `upload.txt` |

### 1.4 重名不覆盖

`unique_upload_name` 在目录里查重,同时也避开同一批上传里已用过的名字。
`report.pdf` 已存在时,新文件存成 `report_2.pdf`,再来一个是 `report_3.pdf`。

### 1.5 写盘

文件用 `O_CREAT | O_EXCL | O_NOFOLLOW` 创建:

- `O_EXCL`:文件已存在就失败,只新建不覆盖。
- `O_NOFOLLOW`:目标是符号链接就拒绝,不会被引导写到别处。

落点是宿主机的 `sandbox_data/sessions/<id>/uploads/`。Agent 在沙箱里看到的是
`/workspace/uploads/<文件名>`,而且这个目录在 bwrap 里是**只读挂载**,Agent 改不了、删不了原件。
想加工就复制到 `scratchpad/` 或 `output/`。

### 1.6 上传时不做任何处理

上传只负责放进目录并记录,**不提取文本,不建索引**。
原因是很多上传的文件 Agent 根本不会读全文,提前处理是浪费。文本转换推迟到 Agent 真正要读的时候(下一节)。

## 2. 读取文件内容

Agent 有两条路读上传的文件:

- **bash / python**:在沙箱里直接处理原文件,适合统计、转换、批量处理。
- **`view_file` 和 `search_document`**:拿到文本给模型看。这两个工具需要先把文件变成文本。

简单文本(txt、md、csv、json 等)直接读。其他格式要转换,**转换在沙箱里执行**
(解析不可信文件的代码不该跑在后端进程里),结果写到 `scratchpad/_rag/`,后端读回后立即删除:

| 格式 | 做法 | 保留的位置信息 |
|---|---|---|
| PDF | pymupdf 逐页提取 | 页码 |
| PPTX | python-pptx 遍历每张幻灯片(含组合形状、表格) | 幻灯片编号 |
| DOCX | python-docx 按文档顺序,每个非空段落一项 | 段号 |
| 其他(xlsx、doc、html 等) | markitdown 转 Markdown | 仅行号 |

位置信息是后面"引用"功能的基础(见 [03](03-文档检索与引用.md)):提取时就按页、按幻灯片分开,
才能让检索结果指回"第几页"。

两个已知限制:

- 文本提取没有 OCR。扫描版 PDF 每页是图片,`view_file`/`search_document` 拿到的是空文本;需要时 Agent 可以按 pdf 技能在沙箱里用 tesseract(含中文语言包)识别。
- DOCX 的页眉页脚、脚注、批注、文本框不会被提取。

## 3. 交付产物:`present_files`

Agent 在 `scratchpad/` 里把文件做好,并不等于用户拿到了。必须调用 `present_files`,
文件才会进入 `output/`,出现在前端的下载列表里。这个"显式交付"动作是检查和归档的挂载点。

### 3.1 单个文件的处理顺序(`tools/executor.py::present_container_files`)

```
源文件 ──► ① 结构自检 ──► ② 归档旧版本 ──► ③ 复制到 output/ ──► ④ 记录摘要
            │ 失败
            └─► 报错给模型,output/ 里的旧文件完全没动
```

顺序是有意安排的:**所有可能失败的检查放在前面,会改动 `output/` 的步骤放在后面**。

**① 结构自检**(`deliverable_check.py`)。只回答"这个文件是不是完整、能打开",不判断内容对不对:

| 类型 | 检查 |
|---|---|
| 任何文件 | 0 字节算失败 |
| docx / xlsx / pptx | 必须是完整的 zip,含 `[Content_Types].xml` 和主文件(`word/document.xml` 等),主文件是合法 XML,zip 内无损坏项 |
| PDF | 文件头是 `%PDF-`,末尾 2 KB 内有 `%%EOF`(写到一半被中断的 PDF 会缺这个) |
| JSON | 能按 UTF-8 解析 |
| CSV | 能按 UTF-8 或 GB18030 解码,无 NUL 字节,引号闭合;**不检查各行列数是否一致** |
| 其他 | 不检查 |

只用标准库做检查,不引入 Office 解析依赖。

**失败时的重试机制**。举例:模型生成 `report.docx` 时写文件中途出错,得到一个半截 zip。

1. 第 1 次 `present_files`:自检失败,返回"未通过交付前检查:不是完整的 zip 压缩包。output/ 中的旧版本未被改动。第 1/2 次修复机会"。
2. 模型修好重试,若仍失败,第 2 次同样报错。
3. **第 3 次仍失败时放行**,照常交付,但返回一条警告,要求模型在回答里如实告诉用户"这个文件可能有问题"。

放行是为了防止模型修不好时无限重试。失败次数按(会话, 文件名)计,通过一次就清零,表最多记 1024 项。

**② 归档旧版本**(`file_versions.py`)。见下一小节。

**③ 复制到 `output/`**。源文件在宿主机上能直接读时就地复制,否则让沙箱容器复制出来。
`output/` 对 Agent 可写,所以复制全程用描述符(`host_files.copy_regular_atomic`):
从会话根逐段打开目标目录,在里面用 `O_EXCL | O_NOFOLLOW` 建一个随机名的临时文件,**一直用这个句柄写入**,不按文件名重新打开;
rename 到目标名之前和之后都核对 inode,临时名被换成链接就不发布,发布后被换掉就撤回。
同名位置原来是 Agent 放的符号链接也没关系,rename 只替换链接本身,不会写到链接指向的地方。
归档和复制可能是几十 MB 的读写,放在线程里做,不卡住其他会话的事件流。

**④ 记录摘要**。交付记录里写入文件的 SHA-256 和大小,用途见 3.3。

### 3.2 版本归档:覆盖同名文件时旧内容去哪了

Agent 常常反复改同一个文件(`report.docx` 改三遍)。每次交付都会覆盖 `output/report.docx`,
所以覆盖之前要把旧内容留下来。版本放在会话目录的 `versions/` 下,**不在沙箱挂载里**,Agent 的命令碰不到:

```
sessions/<id>/versions/report.docx/
    .current          ← 最近一次交付的副本(隐藏文件)
    1730000000000000000   ← 历史版本,文件名是旧文件的 mtime(纳秒)
    1730000100000000000
```

规则:

- **`.current` 独立于 `output/`**。Agent 在 `output/` 里随意改写文件,不影响 `.current`。
  再次交付时,如果新内容和 `.current` 不同,`.current` 就被转存为一份历史版本,然后用新内容更新 `.current`。
- **内容相同不重复存**:逐块比较字节,不用 mtime 和大小判断,因为 Agent 可以保持文件时间不变。
- **只保留最近 5 份历史**,超出的最旧版本被删除;**超过 20 MB 的文件不留版本**。
- **两步提交**:`archive_previous` 在复制前只确定"要归档谁",`finish_archive` 在复制成功后才真正归档和更新 `.current`。
  更新 `.current` 用"写临时文件再改名",复制中途失败时上一次成功交付的副本仍然完好。
- 老会话(没有 `.current`)第一次覆盖前,会直接备份当前 `output/` 里的文件。
- 删除会话时版本一起清掉。

### 3.3 为什么记录 SHA-256:旧消息里的下载链接

对话里有三轮都交付了 `report.docx`,内容各不相同。第一轮那条消息里的下载链接,应该下到第一轮的内容,
而不是 `output/` 里现在的最新版。

做法:交付记录里存了当时文件的 SHA-256 和大小。点开旧链接时,`find_delivered` 按下面的顺序找内容与摘要一致的文件:

1. `output/` 里的当前文件
2. `.current`
3. 历史版本,从新到旧

先按大小跳过明显不符的候选,再分块算摘要,对上了才整份读入;读完再校验一次摘要(两次读取之间文件可能被改写)。
都找不到(版本被裁掉、文件超过 20 MB)就返回 None,接口(`GET /files/delivered`)回 410,提示"该版本已不在保留范围内,请下载最新版本"。

## 4. Office 文件预览(`file_preview.py`)

浏览器不能直接显示 docx / pptx / xlsx,所以先用沙箱里的 LibreOffice 转成 PDF,前端复用 PDF 预览。
支持 docx、doc、pptx、ppt、xlsx、xls、odt、odp、ods。

一次预览请求的过程:

1. **校验路径**:必须在 `uploads/` 或 `output/` 里(对解析后的路径判断,`output/../scratchpad/x` 绕不过去),源文件不超过 50 MB。
2. **算内容 SHA-256**,查缓存。键是(会话, 路径, 内容摘要)。不用 mtime,因为 mtime 可以被保留或回拨。
3. 命中就直接返回。没命中:
   - **合并并发请求**:同一文件已有转换任务在跑,就等它,不再起第二个。某个请求断开也不会取消别人在等的任务(`asyncio.shield`)。
   - **限流**:全局同时最多 2 个转换(信号量)。
   - **隔离执行**:在独立的 bwrap 里跑 LibreOffice(`run_isolated`),不占会话 shell 的锁,所以转换和 Agent 的命令可以并行。超时 90 秒。
   - 转换产物写在 `scratchpad/_preview/<哈希>/`,读回内存后立刻删掉,不占配额、不进快照。
   - PDF 超过 30 MB 报"转换结果过大,请下载查看"。
4. **转换期间源文件被改了**,结果只返回、不缓存,避免缓存里放着和文件对不上的 PDF。
5. 缓存最多 6 项(LRU),在进程内存里。

**预热**:一轮结束后,对本轮新交付的 Office 文件(最多 3 个)提前转换,用户点预览时多半已经在缓存里。
预热尽力而为,失败静默跳过。

## 5. 小结

| 问题 | 做法 |
|---|---|
| 超大上传 | 分块读,超限立即中止 |
| 文件名进 shell | 清洗为安全字符,重名加序号 |
| 上传的原件被改 | `O_EXCL` 写入,沙箱内只读挂载 |
| 交付损坏文件 | 自检,最多 2 次修复机会,第 3 次放行并警告 |
| 覆盖丢失旧内容 | `.current` + 最近 5 份历史,两步提交 |
| 旧链接指向新内容 | 交付记录里存 SHA-256,按摘要找回 |
| 预览卡住 Agent | 独立 bwrap,并发 2,摘要缓存,请求合并 |
